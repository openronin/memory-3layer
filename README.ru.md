# memory-3layer

Память для агентов-программистов: обычные markdown-файлы вне какого-либо агента. Переходите на новую машину или другого агента, подключаете своё хранилище, и работа продолжается с того же места.

[English version](README.md)

## Зачем

Агент теряет контекст при каждой компакции, новой сессии и смене машины. Встроенная память харнесса остаётся в этом харнессе на этой машине. Здесь память лежит в файлах, которые можно читать, сравнивать и синхронизировать через git.

Автоматического сбора нет. Агент ведёт рабочее состояние по ходу дела, а в долгосрочную память факт попадает, только когда вы об этом скажете.

## Как это работает

Каждый факт идёт в слой по тому, сколько он живёт и кому нужен:

| Слой | Файл | Загружается | Что хранит |
|---|---|---|---|
| L0 | `<data>/identity/IDENTITY.md` | каждая сессия | кто вы, жёсткие предпочтения; не больше 25 строк |
| L1a | `<repo>/CLAUDE.md` | каждая сессия в репозитории | команды, правила, индекс документов |
| L1b | `<repo>/.claude-docs/*.md` | по необходимости | архитектура, соглашения, `gotchas.md` |
| L1 запасной | `<data>/projects/<key>/project.md` | каждая сессия | заметки о проекте без подходящего репозитория |
| L2 | `<data>/projects/<key>/SESSION.md` | каждая сессия, после каждой компакции | цель, состояние, решения, последние реплики |
| Архив L2 | `<data>/projects/<key>/SESSION.archive*.md` | только через поиск | закрытая работа, вынесенная из L2 |

`<data>` это `~/.local/share/memory-3layer`. L1a и L1b коммитятся вместе с кодом, поэтому их видят коллеги и серверные агенты. Правило выбора: *понадобится ли это серверному агенту в полночь, без памяти и без человека?* Если да, это идёт в репозиторий.

`<key>` это git remote проекта, например `github.com/owner/repo`, поэтому у проекта одна память на всех машинах, в рабочих копиях и ветках. Проект без remote использует путь относительно `$HOME` или ключ, заданный через `memory-3layer pin`.

Механическую часть делают хуки:

| Событие | Что происходит |
|---|---|
| Старт сессии | Получить данные из хранилищ, сказать агенту, что читать, предупредить, если `SESSION.md` устарел или слишком велик |
| Перед вызовом инструмента | Не дать записать секрет в память, разрешить запись в каталог памяти |
| Перед компакцией | Напомнить агенту сохранить состояние, отправить данные в фоне |
| Конец сессии | Отправить данные в фоне |

Значения секретов не попадают в память. В ней лежит `secret://<name>`, а значение остаётся на этой машине в `~/.local/share/memory-3layer-secrets`; его защищают права на файл, шифрования нет.

Полные правила для агента: [CLAUDE.md](CLAUDE.md).

## Установка

Claude Code:

```
/plugin marketplace add openronin/memory-3layer-claude-code
/plugin install memory-3layer@memory-3layer
```

Перезапустите сессию. Пока не задано хранилище, ничего не покидает машину.

Другие способы и необязательные инструменты: [INSTALL.md](INSTALL.md). Codex CLI, ещё не проверенный на настоящем Codex: [docs/codex.md](docs/codex.md). Переход со старой версии: [docs/migration.md](docs/migration.md).

## Использование

В сессии вы в основном просто говорите с агентом: «запомни» или «remember» переносит факт в долгосрочную память.

| Команда | Что делает |
|---|---|
| `/recall <запрос>` | Поиск по памяти всех проектов |
| `/codemap def\|callers\|callees\|outline <символ>` | Карта символов текущего репозитория |
| `/memory status\|auto on\|auto off\|refresh\|rotate` | Управление памятью; `rotate` выносит закрытую работу в архив |
| `/memstat` | Процессы поиска и прогресс индекса |

В Claude Code навыки плагина называются `/memory-3layer:recall` и так далее. Клиент:

```bash
memory-3layer sync init <git-адрес>     # задать хранилище по умолчанию
memory-3layer sync status               # состояние каждого хранилища
memory-3layer secret put <name>         # сохранить секрет, затем писать в память secret://<name>
memory-3layer key                       # ключ этого проекта
memory-3layer                           # все команды
```

Синхронизация между машинами, в том числе раздельные хранилища для рабочих и личных проектов: [docs/sync.md](docs/sync.md).

## Разработка

```
bin/memory-3layer     клиент: пути, ключи, контекст сессии, migrate, import, search
bin/memory-sync.sh    синхронизация и маршруты
bin/memory-secrets.sh хранилище секретов, сканер, защита записи
bin/codemap.sh        карта символов
bin/memstat.sh        монитор процессов поиска
hooks/                скрипты хуков, общие для всех харнессов
commands/             слэш-команды; пакет превращает их в навыки
CLAUDE.md             протокол; пакет превращает его в навык protocol
harness/<name>/       манифесты, подключение хуков и импорт памяти одного харнесса
templates/, memory/   шаблоны L0, L1a, L1b и запасного L1
tools/package.sh      сборка пакета для одного харнесса
tools/publish.sh      публикация пакета в его репозиторий
install.sh            ручная установка в ~/.claude
```

Тесты на bash, они же запускаются в CI:

```bash
for t in tests/*-test.sh; do bash "$t"; done
```

Аннотированный тег `vX.Y.Z` выпускает всё сразу: workflow запускает тесты, публикует `memory-3layer-claude-code` и `memory-3layer-codex` и создаёт релиз на GitHub из тела тега. Репозитории пакетов генерируются, поэтому изменения вносятся здесь.
